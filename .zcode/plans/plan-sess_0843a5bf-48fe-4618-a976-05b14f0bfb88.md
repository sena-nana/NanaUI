## 目标

把 HTML5 结构与媒体标签补进 `crates/nana-ui-vue/src/widget_map.rs` 的映射表，让这些标签获得明确语义映射而非静默 Column 兜底。不新增 Runtime 控件（最小设计），无对应控件时按 iframe 先例显式 skip 到 Box 并注释说明。

## 改动 1：widget_map.rs 映射（两处同步：`is_html_tag_name` 白名单 226–314 行 + `resolve_kind_from_hints` match 137–200 行）

**结构标签**
- `figure` → Column（块级容器）
- `figcaption` → Text（与已有 `caption`/`summary` 同类）
- `hgroup` → Column（标题组容器）
- `address` → Text（块级文本）
- `menu` → List（HTML 语义等价 `ul`）
- `datalist` → Column（数据容器，无独立控件；建议交互经 `input` 关联，注释说明）
- `col` / `colgroup` → Box（Runtime `Table` 无列定义，显式 skip 注释）
- `slot` → Column（Vue slot 已由 runtime 展开，host 仅兜底）

**媒体标签**
- `picture` → Column（容器；子 `img` 照常绑定 src）
- `source` / `track` → Box（媒体子资源，无视觉，同 SVG 形状做法）
- `audio` → Box + 显式 skip 注释（`WidgetKind` 无 Audio 控件；按硬约束禁止伪播放器，后续复制 `video` 宿主管线路径再打通）
- `embed` / `object` → Box + 显式 skip（与 `iframe` 同类外部内容）
- `map` → Column；`area` → Box（image map 热区不支持，显式 skip）

## 改动 2：核查同步点（防止碰撞与双表不一致）

- `packages/nanavue-runtime/src/createNanaRenderer.js`：确认 `createElement` 普通 tag 直接透传 host op，无需要同步的 tag 表（SVG_TAGS/RETIRED 列表不受影响）。
- `crates/nana-ui-web-api/src/shim.js` 的 `parseHtmlFragment`：确认新标签能通过 innerHTML 片段解析。
- `tree.rs:4623` 的 `"menu" => AccessibilityRole::Menu` 兜底与 `menu`→List 的相互作用：确认 `menu` 标签产出的 List 控件不会被误标 Menu role（若冲突则参照 `tree.rs` 中 `<search>` 布局碰撞排除先例处理）。
- `tree.rs` 的 `resolve_widget_component_type`（3159 行）：确认 `menu`/`picture` 等 tag 不与 Runtime 注册 tag 碰撞，`try_tag` 路径正确落到 kind 的 element_tag。
