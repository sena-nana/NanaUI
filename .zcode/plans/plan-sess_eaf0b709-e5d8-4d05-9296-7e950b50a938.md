# 打通 `<video>` tag — 实施计划

## 目标与边界

`<video>` 从"poster 占位 Box"打通为完整管线:**tag 解析 → Runtime `nana.video` 控件 → host-texture 每帧脏上传采样**,框架提供宿主推帧接口与 play/pause/ended 事件;解码(demux/decode)留在消费应用。不碰未提交的 a11y WIP(renderer.rs/tree.rs 里他人的 AccName/landmark 改动,与 video 正交)。

## 一、Runtime 控件 `Video`(nana.video,单 tag "video")

新文件 `crates/nana-ui-runtime/src/video.rs`,结构镜像 `GpuTextureView`(gpu_slots.rs:192-473):

- 字段:`resource: Arc<str>`、`generation`、`version`、`opacity`、`corner_radius`、`fit: ContentFit`、`style: NodeStyle`、`pointer_events`(默认 false)、语义状态 `autoplay` / `loop` / `muted`(声明式,来自 Vue attrs;实时播放真值在宿主侧推帧器,不在 Runtime)。
- `custom_render()`:`CustomRenderNode::new(HOST_TEXTURE_RENDERER, resource, revision)`,resource 为空返回 None(同 GpuTextureView:268-280)。
- `ComponentView::project`:custom_render 差异化 `set_custom_render` + `project_common`;a11y role 用现有最接近的角色(GpuTextureView 用 `AccessibilityRole::Image`,实现时核对本子有无更贴切项)。
- `RegisterableComponent`:`TYPE_ID = "nana.video"`,`TAGS = &["video"]`;`from_semantic` 读 `data-nana-video`(数字 id > 0 → 资源 `video:{id}`)、`fit`、`pointer-events`、`autoplay`/`loop`/`muted`。
- 注册:`builtin_components.rs` `install()` 加 `registrar.register_component::<Video>()`。

## 二、Vue facade

1. `bridge.rs`:`WidgetKind::Video` 变体 + `parse`("video") + `as_str`("video") + `element_tag`("nana-video") 四处(镜像 GpuTextureView 位置 :180/:268/:348/:427)。
2. `widget_map.rs:169`:`"video" => WidgetKind::Video`(原 Box);更新注释(video 不再 poster-only)。`apply_video_poster`(css_paint.rs:332)保留作首帧前回退,不改。
3. `tree.rs` 槽位契约(镜像 canvas):
   - `video_host_texture_slot(id)`:数字 id > 0 → `video:{id}`(与 `canvas_host_texture_slot`:3091 并列)。
   - `surface_host_texture_slot`(:2141)增加 `data-nana-video` 检查;`resolve_widget_component_type` 无需特判——element_tag "video" 直接命中 `resolve_component_tag("video")`(同名同语义路径 :3204)。
4. a11y role 映射:video → 与控件 project 一致的角色。

## 三、推帧接口(框架留接口面,业务自备解码)

新模块 `crates/nana-ui-vue/src/video.rs`(帧存储)+ `video_gpu.rs`(GPU 桥),完全镜像 canvas 模式:

- `VideoId(u64)`;`VideoRuntime`:每 id 最新帧 `{width, height, version(内部单调), bytes(RGBA8), dirty}`;`push_frame`(覆盖最新帧、推进 version)、`take_upload(id, uploaded_version)`(去重 + 脏区)、`contains`、`remove`;`SharedVideoRuntime = Arc<Mutex<VideoRuntime>>`。
- `VideoGpuBridge` 镜像 `CanvasGpuBridge`(canvas_gpu.rs):复用泛型 `HostTextureSlotStore<VideoId>`;slot 名 `video:{id}`(与 tree.rs 契约一致);texture_id 用 `1<<62` 位标记(避开 canvas 的 `1<<63`)。
- 宿主 API(`VueHost`,lib.rs):
  - `push_video_frame(window_id, video_id, w, h, bytes, dirty: Option<Rect>)` — 写入共享 runtime。
  - `set_video_playing(window_id, video_id, bool)` → 解析 `data-nana-video == id` 的节点,`dispatch_bridge_event(BridgeEvent::Native { name: "play"/"pause", ... })`(既有通道 lib.rs:1632/:1679,参考 examples/vue-hosted-acceptance/src/main.rs:441)。
  - `notify_video_ended(window_id, video_id)` → Native "ended"。
- 每帧同步:扩展 `VueHost::prepare_canvas_gpu`(lib.rs:715-741)同时扫描 `data-nana-video` 并 `video_gpu.sync(id)`;GPU 桥随 `bind_host_gpu`/`replace_host_gpu` 共享。
- 多窗口:`multi_window.rs` 镜像 canvas——`VueRuntimeState.video: SharedVideoRuntime`,`VueRuntime::new` 创建/注入(注入式,业务持同一 Arc),`create_window`/`bind_host_gpu`/`replace_host_gpu` 时 `share_video_gpu`。
- 运行时侧不需要新 host op:推帧与状态全在 Rust 宿主接口;`@play/@pause/@ended` 监听器经既有 `patchProp on*` → `set_event_flag` 落 UiWorld EventListeners,零改动。

## 四、行为测试(只测合同,不硬匹配实现)

- Runtime:`resolve_component_tag("video") == "nana.video"`、HTML tag 别名合同(video 不被布局 tag 占用);`from_semantic` attrs → 字段;`custom_render` 资源 `video:{id}`、空资源 None。
- Vue:`WidgetKind::Video` parse/as_str/element_tag;widget_map 更新 `canvas_video_iframe_map_to_box`(video → Video,canvas/iframe 不变);tree 端到端 `component_type(id) == "nana.video"`;槽位契约 `data-nana-video="7"` → renderer `nana.host-texture` + resource `video:7` + revision 盖章(`override_host_texture_revision` 已有测试钩子);`@play` 监听 flag 落 EventListeners。
- `VideoRuntime`:version 单调、sync 前多次 push 只留最新、`take_upload` 去重。
- `packages/nanavue-components/SEMANTICS.md` 补 video 语义行(如 exports.test.mjs 涉及则同步)。
