# 预留 WebSocket 接口（业务/宿主自备实现）

## 结论

可行。fetch 已经建立了"缓冲式 host op + 白名单 + 宿主注入实现"的完整范本，WS 走同构路径，不引入新管道、不引入 tokio、框架不写任何网络传输代码。宿主不注入实现时 `new WebSocket()` 直接抛错，网络职责仍留在框架外。

## 改动

### 1. `crates/nana-ui-platform/src/ws.rs`（新增）— trait 与策略

镜像 `fetch.rs` 的结构：

- `SocketPolicy`：`allowed_origins: BTreeSet<String>`（默认空 = 全拒绝，仅接受 `ws`/`wss` origin，镜像 `FetchPolicy` 与 `default_policy_denies_every_origin` 测试）、`max_message_bytes`。提供 `allow_origin` / `with_allowed_origin` / `authorize(&Url)`。
- `WebSocketHost` trait（镜像 `FetchHost`，业务完全自实现传输）：
  - `policy() -> &SocketPolicy`
  - `open(request: WsOpenRequest, sink: Arc<dyn WsSink>) -> Result<WsHandle>`：request 含 url/protocols；`WsSink` 由框架提供，业务实现把 open/message/close/error 事件推入。
  - `send(&self, handle, message)`、`close(&self, handle, code, reason)`。
- 共享句柄别名 `SharedWebSocketHost = Arc<dyn WebSocketHost + Send + Sync>`。

### 2. `crates/nana-ui-web-api` — SocketRuntime + host ops + 唤醒

- `src/ws.rs`（新增）`SocketRuntime`：持有 `SharedWebSocketHost`（Option，无 host = 未启用）；内部事件通道接收 sink 推来的 inbound 事件（镜像 fetch 的 unbounded completions）；`drain_socket_events() -> Vec<HostValue>`、`has_open_sockets()`。
- host ops（`register_web_socket_ops`，挂进 `register_web_api_storage_and_timer_ops` 既有链）：
  - `wsOpen`：先 `host.policy().authorize(url)`（拒绝同步抛 JsException），再调 `host.open`，同步返回数字 id（镜像 `fetchStart`）。
  - `wsSend` / `wsClose`：按 id 转发；连接不存在或已 CLOSING 时抛错。
- `WebApiState`：新增 `socket: SocketRuntime` + `with_socket_host(...)` / `shared_web_api_state_with_socket(...)` 便捷构造。
- `WebApiState::next_wakeup`：有活跃 socket 时返回有界唤醒（同 fetch 的 8ms 模式，`lib.rs:284`），空闲返回 None。

### 3. `shim.js` — 最小子集 WebSocket 类

- `WebSocketShim`：`constructor(url, protocols)`（校验 ws/wss；无宿主注入时抛 `TypeError: WebSocket is not available`）、readyState 四常量、`send(string | ArrayBuffer | typed array)`、`close(code?, reason?)`、`onopen/onmessage/onclose/onerror` + `addEventListener/removeEventListener`、轻量 `MessageEventShim`（仅 `data`）。不模拟 `binaryType`/`bufferedAmount`/浏览器扩展事件。
- `globalThis.__nanaDrainWs(events)`：按 kind 分发到对应连接的 handler，关闭后清理 pending 表（结构镜像 `__nanaDrainFetch`）。
- `globalThis.WebSocket = WebSocketShim`。

### 4. 注入点与泵

- `MountOptions.socket_host: Option<SharedWebSocketHost>`（`nana-ui-vue/src/app.rs`，镜像 `fetch_host`），`mount_vue_as_nana` 传入 `WebApiState`。
- `VueHost::pump_frame`：在 drain fetch completions 旁增加 drain socket events → `engine.invoke(__nanaDrainWs, ...)`；`next_wakeup` 已聚合 `WebApiState::next_wakeup`，socket 唤醒自动生效。
- `crates/nana-ui` crate-root 再导出 `WebSocketHost` / `SocketPolicy` / `SharedWebSocketHost` 等公开类型。

### 5. 测试（行为测试，镜像 fetch 既有模式）

- 无宿主注入：`new WebSocket()` 抛错。
- `SocketPolicy` 默认全拒绝、白名单放行/拒绝、非 ws/wss scheme 拒绝。
- 用内存 fixture `WebSocketHost`（镜像 nana-js-v8 的 fixture fetch host）走 open→message→close 全链路，事件按序到达 JS handler。
- 状态机：CLOSING/CLOSED 后 `send` 抛错。
- `next_wakeup`：活跃 socket 给有界唤醒，空闲返回 None。
- drain 不阻塞 JS 线程（镜像 fetch 的对应断言）。

### 6. 文档

- `docs/vue.md` 把 WebSocket 从"不支持"清单（L45）移到"预留接口、宿主提供实现"条目，说明注入方式。

## 验证

`cargo test` 覆盖 platform / web-api / vue 三个 crate 的新增与受影响测试；本改动不涉及 GPU、渲染与视觉路径，无需快照或 GPU 验证。

## 明确不做

- 框架内不实现任何 WS 传输（无 tungstenite/tokio 依赖）。
- 不引入 `Live2D` 式的第二套通道，不绕过 `PendingHostOps` / pump_frame 合同。
- 不做 `HostEventSender` 推送路径——统一走 fetch 已确立的每帧 drain，避免双通道。
