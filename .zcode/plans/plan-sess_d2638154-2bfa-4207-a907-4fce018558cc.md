# HTML 地标 a11y role 落地计划

## 目标

为 HTML 地标元素补 `AccessibilityRole` 语义：`<nav>`→navigation、`<main>`→main、`<aside>`→complementary、`<search>`→search、`<header>`→banner、`<footer>`→contentinfo、`<section>`（有名时）→region、`<form>`（有名时）→form。**不改变任何控件映射决定**：`<search>` 仍为 Column 布局盒、仍不解析到 SearchDropdown，加的只是 a11y 语义层。

## 设计：role 来源优先级

在 `sync_semantic_styles`（tree.rs:1562）构造 `AccessibilityState` 处改为三级来源：

1. **显式 `role` 属性**（现有行为，最高优先，用户写 `role="button"` 可覆盖一切）
2. **地标标签**（`widget.props.element_tag`，新增）
3. **WidgetKind 兜底**（现有行为）

条件门槛：`<section>`/`<form>` 仅在有可访问名（label 非空）时升级为 region/form，否则保持 Generic（遵循 HTML-AAM 规范）；`<header>`/`<footer>` 无条件映射（"仅顶层才算 banner/contentinfo"的祖先判断暂不做，在 docs 中记录该偏差）。地标 role 仅在 `widget.kind.is_layout()` 时生效，避免覆盖 class hints 解析出的控件语义。

## 改动清单

### 1. Runtime 枚举 — `crates/nana-ui-runtime/src/components.rs`（:1264 起）

`AccessibilityRole` 在 `Generic` 前新增 8 个变体：`Main`、`Navigation`、`Banner`、`ContentInfo`、`Complementary`、`Region`、`Search`、`Form`。枚举仅 derive Copy/Eq/Default，无序列化影响。

### 2. accesskit 投射 — `crates/nana-ui/src/accessibility.rs`（`project_role` :701）

补 8 个臂映射到 accesskit 对应 Role。实现时核对 Cargo.lock 中 accesskit 版本的 `Role` 枚举是否有 Banner/ContentInfo/Complementary/Navigation/Main/Region/Search/Form 直接等价物（accesskit 镜像 UIA 地标集，预期都有）；个别缺失的映射到最近似角色并在代码注释说明。确认 `supports_click`/`supports_focus`（:630/:642）白名单默认不含新 role（地标不可点、不可聚焦，无需改动，但需验证）。补单元测试（仿 :749 起的写法）。

### 3. devtools dump 命名 — `crates/nana-ui-devtools/src/agent.rs`（`accessibility_role_name` :599）

补 8 个臂，用 ARIA role 字符串：`"banner"`、`"contentinfo"`、`"complementary"`、`"form"`、`"main"`、`"navigation"`、`"region"`、`"search"`（agent dump 与 Vue 显式 role 字符串共用同一套词表）。

### 4. Vue 投影 — `crates/nana-ui-vue/src/tree.rs`

- `accessibility_role`（:4473）显式字符串臂补上以上 8 个 ARIA 名。
- 新增 `landmark_role_from_tag(tag: &str, has_label: bool) -> Option<AccessibilityRole>` 帮助函数；`sync_semantic_styles`（:1562-1602）中把 `accessibility_role(widget.kind, &widget.props.role)` 改为三级来源逻辑。
- 行为测试（仿 tree.rs:6640 `semantic_widget_accessibility_projects_from_runtime` 的断言写法，用 `project_accessibility` 断言 role）：
  - `createElement("nav")` → `Navigation`；`createElement("search")` → `Search`（同时确认现有 `html_search_landmark_is_not_search_dropdown`、framework.rs:10773 的测试仍绿——不碰控件映射）；
  - `<header>` → `Banner`、`<footer>` → `ContentInfo`、`<aside>` → `Complementary`、`<main>` → `Main`；
  - `<section>` 无 label → `Generic`，有 label → `Region`；`<form>` 同理 → `Form`；
  - `<nav role="button">` 显式 role 覆盖 → `Button`（显式优先）。

### 5. 文档 — `docs/vue.md`

在映射/语义说明处补一段：地标标签现携带 a11y landmark role；`<search>`/`<form>` 仍是布局盒（控件仍用 `search-dropdown`/`form-field`）；记录 header/footer 未做"仅顶层"判断的偏差。

## 验证（按 $nanaui-validation）

- `cargo test -p nana-ui-runtime -p nana-ui-vue -p nana-ui -p nana-ui-devtools` 全绿（含所有既有 role 测试）。
- 无头验证：用 `nana-agent-session`（$nanaui-agent-debug）对一个含 `<nav>/<main>/<search>` 的 Vue 页面跑 a11y dump，确认 dump 中出现 `navigation`/`main`/`search` role 字符串——这是真实消费端证据，不止单测。
- 不涉及 GPU/视觉改动，不需要快照或 GPU 验证。
