# 反向轴上的顺序回放（#59）

`0259fc972` 让容器计划的顺序回放在反向轴上也启用（摆放改为流相对，只在写子项坐标时换算）。这里量它对
dirty-frame 的影响。

## 做法

- 形状：`layout`（LTR 对照）、`layout-rtl`（列表容器 `direction: rtl`，交叉轴反向）、`layout-reverse`
  （`column-reverse`，主轴自下而上）。每帧改 1 行的高度；`tail` 改最后一行，`head` 改第一行。
- A/B：「之前」只把 `place_node_scoped` 里 `plan_sequential` 那一行恢复成
  `cacheable && !main_reversed && !cross_reversed`（等价于 `0259fc972` 之前的行为），其余代码相同，
  所以两边都能读新计数器。两个二进制交替运行，两种先后顺序各一轮，每格读两轮中的**最小值**
  （本机负载常年 5–15，单次 p50 会跳；这轮开跑时 load average 5.8）。每次 200 样本、40 预热。
- 结构性证据：`layout_plan.children_measured`（每帧兄弟扫描次数）与 `suffixes_replayed`（每帧后缀回放次数），
  均为每帧均值。
- 复现：先构建两个二进制放到同一目录（`bench-before` / `bench-after`），再跑 `ab.py`。原始结果在 `ab-results.json`。

## 结论

- **`tail`：从 O(N) 变成常数，与 LTR 一致。**之前 RTL / `column-reverse` 列表改最后一行也要重扫全部兄弟
  （子项测量 = 行数 + 1，回放 0 次），8,002 节点时 0.72 ms；之后每帧只测 1 个子项、回放 1 次，0.007 ms，
  **约 100 倍**，且不随规模变化。
- **`head`：本来就欠 O(N)**（改第一行，其下每一行都要动），时间基本不变（差 0–10%，在噪声范围内）；
  但兄弟扫描减半——之前测两遍（完整摆放 + 固有尺寸），之后回放只测一遍，与 LTR 相同。
- **LTR 对照**两边完全一样，计数器相同，说明改动只作用于反向轴。
