# Runtime and Scene render extraction contract

This page is for framework maintainers changing `nana-ui-runtime` (the retained tree) or `nana-ui-scene` (draw graph extraction and compositing). For the application-level mental model, see [How the framework works](how-it-works.md); for host entry point signatures, see [Application API](application-api.md).

The product path is strictly one-directional: `UiWorld` → `ExtractedNode` → `UiScene` → `SceneWgpuPainter`. Neither `nana-ui-runtime` nor `nana-ui-scene` **depends on WGPU**; `nana-ui-scene` holds no application business state, window handles, or GPU device objects.

## 1. `UiWorld` as the single authority

Escape first closes a dismissible Popover / ActionMenu inside the currently active Panel / Dialog, and only then closes the outer card.
A menu in a background card cannot steal Escape from a foreground modal; one key press ends only the current layer of interaction.

`UiWorld` is the sole authority for all of the following state: node identity (`StableNodeId`), document ownership (`DocumentId`), parent/child hierarchy, node kind, computed style, text and committed selection, unscrolled layout boxes (`LayoutResult` / `LayoutBox`), scroll offset (`scroll_offset`), pointer hover / press / capture state, the event routing table, the focus chain and IME, the accessibility projection, text presenters, and custom render slot declarations.

- **External identity isolation**: only `StableNodeId` and typed `Entity<V>` are exposed externally. Evolving the internal node table's storage layout must not invalidate external handles, diagnostic records, or persisted data.
- **Atomic batch commit**: structural changes are first queued in the frame's `MutationQueue` and committed at once only after the whole batch validates. A failed validation leaves no half-built hierarchy, and IDs of destroyed nodes are never reused.

## 2. Incremental frame scheduling and motion lifecycle

Runtime deterministically builds per-stage work lists (style, text shaping, layout, hit index, focus and IME, accessibility, render extraction) from each node's dirty mask (`DirtyMask`). A quiescent `UiWorld` returns an empty work set and does not request continuous redraws. A local mutation propagates only to semantically affected nodes and stops at any node already in the same dirty state.

`RuntimeDocument::flush` calls the host's `TextShaper` within a single bounded frame transaction, and then `RuntimeLayoutEngine` writes layout back from the viewport, styles, and shaping metrics. When the viewport size changes, only the document root, `position: fixed` nodes, and boxes that consumed a constraint on the changed axis (such as `vw` / `vh`) seed an incremental relayout; unaffected subtrees reuse the retained cache directly. If the frame transaction does not converge, the dirty work already taken is returned to the scheduler, and no Scene or accessibility delta is published until it settles.

### Unified Motion IR and completion event guarantees

All animations (Rust L3's `ViewContext::transition`, `Spring::to`, `Timeline::parallel | sequence`, the hover / switch / spinner / sidebar transitions of built-in controls, and CSS motion) compile into `AnimationSpec` in `nana-ui-core::motion` and are evaluated against a monotonic clock passed in by the host. Runtime creates no timer threads of its own:

- **Exact delivery of completion events**: every started animation is guaranteed to end with **exactly one** `Finished` or `Cancelled` event. A track replaced mid-flight by a new animation with the same ID reports `Cancelled` (matching CSS `transitioncancel`); a track that reached its end but has not yet been reclaimed by `advance_animations` reports `Finished`. Endings triggered by a commit (`stop_animation`, `finish_animation`, replacement, node removal, or parking) are kept until consumed (later commits do not flush them away). As long as an ending event is undelivered, `next_animation_deadline` reports the current animation time to wake the host for dispatch, regardless of whether the window is presenting. For a spring animation slightly slower than its estimated settle time, if it has not settled at the estimate it keeps checking at the next frame interval instead of getting stuck at `Duration::MAX`.
- **Visibility lifecycle for persistent nodes (`PresenceLifecycle`)**: manages persistent nodes whose visibility toggles with a fade (optionally with a translation), such as tool window panels, floating cards, and transient toolbars. It reuses the view layer's `Transition` description for enter and exit. Calling `set_shown(cx, shown, now)` starts directly from the current presented value (reversing mid-flight is a retarget) and **writes only compositor tracks, never logical style**. When hiding begins it immediately sets `pointer-events` to `none` and moves focus out of the subtree; when showing begins it restores `pointer-events` (use `set_shown_at_once` when the first mount must be hidden silently). Feed each frame's `AnimationFrame` to `apply_events(cx, &frame.events)`, and when the last track ends it returns `PresenceSettled::Shown` or `Hidden`. After settling hidden it sets the node to `visibility: hidden` automatically (removed from painting, hit testing, and the accessibility tree, but keeping its layout identity). When the system has "reduce motion" enabled, it runs with zero duration and no translation and still reports settling as usual.
- **Final values of overlay exits**: a modal or menu's opacity and translation tracks end independently. An exit track that ends first keeps its final value through forwards fill until a reopen retargets it or the node is destroyed; it does not fall back to the logical style. The host sends `OverlayChanged { active: None }` only after all exit tracks complete, and only on receiving it may the application park the subtree. `OverlayClosing` and a component's `open=false` confirm that it is closed; they do not mean the subtree can be parked immediately. Holding a final value produces no animation wakeups.
- **Sparse sampling separated from wakeups**: `advance_animations` samples CPU / Layout / Paint tracks at `frame_interval`, and registers only two deadlines, start and end, for compositor-safe (`AnimationClass::Compositor`) tracks. `compositor_needs_tick` switches only the window that has active compositor tracks into lightweight present; it does not enter the CPU animation deadline and does not trigger redraws of other windows. "Active" also changes over time: tracks that have finished playing and rest at their final value through forwards fill (the fade-out after a visibility settle, the final value of an overlay exit) and paused tracks do not count. Their layers are kept and their final values still display, but they no longer keep the window producing frames. The hold period while waiting for promotion or demotion still counts.

### Animated property classification

Logical values live in `UiWorld`; transient presented values live in `PresentationStore` (query them through `UiWorld::presentation_pair` or `applied_value()`; never write `transform` or `opacity` back into `UiWorld` every frame):

An opacity animation applies to the composited result of the whole node. A node with children, a custom painter, or compound control painting first draws itself and its child content into one dest isolation group, then applies the current presented opacity once. The card surface, text, and controls must not be faded separately, or overlapping regions would accumulate alpha. The group takes effect from the first frame without waiting for compositor layer promotion, and covers exit, reversal, and the end hold; children's own opacity is still kept inside the group. Opacity carried by the group is no longer passed into CPU primitives or a Quad's GPU motion id. A modal scrim still fades independently outside its card's group, and a triggered menu's trigger does not enter its own overlay's group either (see the next section). The retained paint order and primitives are updated only when group membership changes; time sampling triggers no Runtime extraction, layout, or geometry rebuild. A pure group whose opacity is 1 may skip offscreen compositing.

| Property | Default class | Execution path | Fallback and performance boundary |
| --- | --- | --- | --- |
| `transform` / `opacity` | `Compositor` | Presentation overlay; Quad (including `QuadBatch` / `QuadColorBatch`) strips the overlay and uses GPU `evaluate()`; Text / Icon / Mesh / HostTexture use the CPU overlay | Steady state does not write `UiWorld`; only Quad uses GPU evaluation, to avoid stripping an overlay that the shader cannot reconstruct |
| `clip` / `clip-path` | `Compositor` | Presentation overlay (`compositor_gpu_motion_ids` currently binds only transform / opacity) | Steady state does not write `UiWorld`; clip presentation uses the CPU overlay |
| `shader-parameter` | `Compositor` | Presentation overlay (requires a registered typed codec) | No default Quad GPU path; chart animation uses a dedicated presentation clock (see below) |
| `color` / `background` / `blur` / `filter` / `shadow` | `Paint` | CPU interpolation (sparsely sampled at `frame_interval`) | Each sample may mark paint / extract dirty; no GPU filter evaluation |
| `width` / `height` / `padding` / `margin` | `Layout` | CPU layout evaluation; samples write px and mark `LAYOUT` dirty | Subtree measurement and hit testing both use real geometry; never fake it with `scale` |
| `font-size` / `font-axis` | `Layout` | Non-compositor path (triggers text shaping and layout) | [#85](https://github.com/sena-nana/NanaUI/issues/85) does not force a GPU path |
| `display` | `Discrete` | `snap_discrete` (holds the start value until the end, then switches to the end value) | No continuous interpolation |

## 3. Scene extraction, compositor layer hysteresis, and pixel snapping

`flush` extracts dirty nodes into `ExtractedNode` deltas and hands them to `UiScene::apply_delta` to update the retained draw graph. Compositor-class presentation properties (`transform`, `opacity`, `clip`, `shader-parameter`) are not baked into the logical style of `ExtractedNode`; instead `UiScene::apply_presentation` binds them to a `CompositorLayer` by reference directly from `PresentationStore` and `MotionDescriptorStore` (never clone the descriptor table every frame; advancing time alone never triggers re-extraction).

- **Compositor layer promotion and demotion hysteresis**: a layer's identity is the node's `StableNodeId`. `LAYER_PROMOTE_HOLD` is `16 ms` (momentary flickers shorter than a frame are not promoted), and `LAYER_DEMOTE_HOLD` is `120 ms` (the layer is kept for 120 ms after an animation ends before demotion, so back-to-back animations do not repeatedly build and tear down layers). `OpacityGroup` and `FilterGroup` are dest isolation groups and are not the same thing as a motion layer. A vertically clipped scroll region whose style has `PaintStyle::scroll_edge_fade` is also an `OpacityGroup`: the group's `EdgeFadeMask` records the clip box and two band lengths computed from the current offset, and during compositing alpha falls linearly to 0 across each band by destination pixel row. Group membership depends only on style, so scrolling to either end does not reorder anything; when both bands are 0, `is_identity()` is true and the painter does not composite it. Its scrollbar primitives use the same group with the fade removed (`primitive_opacity_groups`); root-painted floating overlays and menus with `isolate_from_ancestors = true` cut off all outer ancestor `OpacityGroup`s (including `edge_fade`), `FilterGroup`s, scalar opacity, and compositor layer opacity while retaining only the overlay's own open/close fade, whereas non-isolated root overlays and escaping `#201` absolute boxes strip `edge_fade` from any scroll ancestor that no longer clips them while retaining structural ancestor effects. A fade-only group (`is_edge_fade_only`) does not block viewport culling of the subtree.
- **First-frame presentation does not wait for layer promotion**: during `PendingPromote`, Scene keeps a CPU projection of the current Presentation, and painting, ancestor opacity, transform, clipping, and visible-range queries use it from 0 ms on. It does not modify Runtime logical style, create a compositor cache layer, or bind a GPU motion id early. After 16 ms the normal layer takes over; there must never be a frame painted at base opacity=1 that then jumps back to mid-fade. Tracks that end or are removed during the wait clear the temporary projection and invalidate the corresponding paint caches.
- **Pivot and scrim separation for modals (Dialog / ConfirmDialog / Drawer)**: a modal produces both the background scrim and the centered card primitives within a single node. Its motion layer applies to the **card**: the card and its slot content translate, scale, and fade in around the card center (`ComponentGeometry::presentation_pivot`), and hit testing, CPU presentation, and GPU `evaluate()` share the same pivot. The scrim primitives do not stack the node's own opacity track (they inherit only outer ancestor opacity); they fade in independently by `scrim_opacity` from the geometry, and reserve an outward margin for the card's maximum translation and scale so that they always cover the window (single-primitive presentation queries use `UiScene::compositor_primitive_opacity` / `compositor_primitive_encode`).
- **Trigger and overlay separation for triggered menus (Popover / ActionMenu / HoverCard)**: the menu node itself is the trigger that stays in document flow, and its open/close tracks (`MENU_OPACITY` fade-in, `MENU_POP` 0.9→1 scale) belong only to the hanging overlay. The overlay surface (`TRIGGERED_OVERLAY_SURFACE_SLOT`) and the viewport-fixed menu items it places share the node's own open/close fade and scale around the same pivot, which is the point on the overlay surface closest to the trigger's center (`ComponentGeometry::presentation_pivot`). Menu and floating overlay components (`Popover`, `ActionMenu`, `AnchoredActionMenu`, `ContextMenu`, `HoverCard`, `Select`, `Dropdown`, `SearchDropdown`, `Tooltip`) default to `isolate_from_ancestors = true` (which can also be enabled on `Stack` / `NodeStyle`), so the hanging overlay and items are unaffected by ancestor opacity, filters, blend modes, scroll edge fades, and overflow clips, while the in-flow trigger primitives and `trigger_content` subtree remain inside ancestor groups and keep logical style. Pass `.isolate_from_ancestors(false)` when the overlay should fade or filter with its ancestors (plain `position: fixed` boxes and modals keep `false` by default). The overlay's scale is carried by the CPU projection (`UiScene::hanging_transform`; the menu node binds no GPU transform id). Runtime hit testing, accessibility coordinates, `presentation_input_bounds`, and overlay surface hit testing apply the same transform from the same pivot, consistently before and after promotion.
- **Live row dragging in ReorderList**: the dragged row following the pointer and the other rows making room are both compositor transform tracks on the row nodes (following is a hold track replaced as the pointer moves; making room is a transition with Retarget that holds at its end). They do not write the rows' logical style or layout boxes, and the drop position is still decided by layout boxes. A change of drop position restarts tracks only for rows whose translation target changed; pointer movement re-extracts neither the list nor the rows. The dragged row's stacking level `REORDER_PREVIEW_Z_INDEX` is below `MENU_OVERLAY_Z_INDEX`, and the dragged subtree is re-extracted only once each at drag start and drag end. When the drag ends (release, Escape, `Cancel`), all tracks are cancelled and no presentation is left behind.
- **List reorder FLIP**: after the end (Last) layout is committed, only one compositor translation track plays (in L3, `node().flip(first, last)`, optionally with `animate_size()` opening a separate Layout-class width/height track).
- **Device pixel snapping**: the painter snaps the **final composited pure-translation component** of each primitive and of every level of its clip regions to whole device pixels (`clip::paint_transform`; rotation, scale, and perspective components are unchanged). Scroll offset, CSS `translate`, and the reverse translation of frozen rows and columns are first combined into a total translation and snapped once, which guarantees that Quads, icons, text, path meshes, HostTextures, and clip edges under the same scroll container always move by the same number of whole pixels. Meanwhile `ScrollOffset`, hit testing, and accessibility bounds keep floating-point precision, so sub-pixel horizontal trackpad scrolling does not trigger text re-resolution (#223).

## 4. Chart presentation clock

A `Chart`'s entrance, data-update transitions, and hover highlighting do not go through the general Motion IR. The layout stage writes a start `from` and end `to` for each primitive directly (`ChartMarks::transition` records the start time, duration, and easing; hover records `HoverState::since`). When data updates continuously, the new layout's `from` is taken directly from the previous layout's instantaneous interpolated position at the current time, so continuous refreshes are smooth with no jumps.

The chart WGSL shaders compute interpolation progress directly from `motion_time`. When only time advances in a frame, Runtime does not write `UiWorld`, Scene does not re-extract, and the painter does not re-upload vertex data. Scene records the animation's due time through `chart_live` and feeds it into `compositor_needs_tick()`, driving lightweight frames for the window until then and skipping dest cache reuse.

## 5. Clip paths (`clip-path`), drop-shadow filters, and backdrop blur

### CSS `clip-path` and rounded `overflow`

An ancestor's `clip-path` and rounded `overflow` enter the `UiScene::ClipRegion` chain and are routed by complexity to hardware scissor, fragment-shader SDF, or a dest group:

- **Axis-aligned rectangles**: hardware GPU scissor + vertex `FragmentClip`.
- **`clip-path: inset(... round R)` and rounded `overflow`**: the corner radius is written into `FragmentClip.corner_radius` (an exact rounded-rectangle SDF is kept under non-translation transforms or rotation, and the radius is not zeroed; HostTexture shares the same rounded SDF through `clip_inv_ef.z`). A single level of rounded clipping stays in vertex attributes; multiple nested rounded levels or a rotated outer clip are upgraded to a dest group automatically. When everything a primitive drew (the bounds each batched command records) lies inside an axis-aligned rounded clip's rectangle and clear of its `r × r` corner squares, that clip covers it fully and opens no group — the usual case is an input's text inside a rounded card; GPU nodes, masks and groups still open one. The node's own surface (slot 0) gets only a square clip, to avoid double anti-aliasing fills and strokes that are already rounded.
- **`clip-path: polygon(...)`**: Scene stores both an axis-aligned bounding box (AABB) and the local polygon vertices. The node's own Quad does a point-in-polygon test directly in the fragment shader; children, text, and HostTexture are clipped against the polygon by winding number in the compositing pass through a dest group.

### CSS `filter: drop-shadow(...)`

`filter: drop-shadow(offset-x offset-y blur color)` is implemented with a dest group: the subtree is first drawn into a separate group texture layer; compositing samples that layer's **alpha silhouette**, shifts the UVs by the offset, blurs it with the same 5×5 Gaussian kernel as `filter: blur()` and tints it (blur radius capped at `16 px`), and finally places it source-over beneath the original image. Multiple `drop-shadow` layers, `spread`, `inset`, and unknown filter functions are strictly skipped, fail-closed.

### CSS `backdrop-filter: blur(Npx)`

`backdrop-filter: blur(Npx)` is a **per-node** live background blur (unrelated to the whole-window system Mica / Acrylic materials in `nana-window`):

- Before drawing the node's own fill, the painter samples from the current target texture (`dest.color` or an outer opacity-group layer) everything already drawn in document order behind the node's bounding box (including Quads, HostTextures, and custom GPU nodes that precede it), runs a separable Gaussian blur, composites the result back into the node's area using the node's corner radius, `clip-path`, and `mask-image`, and finally overlays the node's own translucent fill or gradient.
- **Downsampling pyramid and edge extension**: the blur radius `r` is a standard deviation in logical pixels (multiplied by the DPI scale into device pixels automatically; the sampling kernel covers $3\sigma$ and uses bilinear sampling to merge adjacent texels, eliminating banding artifacts). When the standard deviation exceeds `8` device pixels, the region to blur is first box-averaged down by powers of two, blurred on the reduced copy, and then bilinearly upscaled, so even a large `64 px` radius needs only a few dozen samples at any scale. Sampling extends edge pixels outward at the boundary (clamp-to-edge), so no transparent black fringe bleeds in at the edges.
- **Tied to node opacity**: the blurred background and the node's fill are both governed by the node's own `opacity`. Translucent frosted glass shows a half-strength blur, and a fading-in modal scrim makes the background blur fade in smoothly with it instead of abruptly blurring the whole area on the first frame.
- **MSAA and target interleaving**: frames that contain HostTexture, custom GPU nodes, dest groups, or `backdrop-filter` all use interleaved compositing on a single-sample target (`sample_count = 1`). Pure vector/text UI frames can draw quads and meshes with `4x MSAA` and draw crisp text after the resolve (never resolving repeatedly on both sides of a custom GPU node).

## 6. Text highlight presentation (`TextPresenter`)

Rich text coloring such as code highlighting is expressed through declarative `HighlightRequest` and `TextPresentation`; the actual lexing algorithm is provided by a `TextPresenter` registered by name (installed through `ExtensionRegistrar::register_presenter`). A presenter reads only committed UTF-8 text and stays monochrome during IME composition (preedit). When the language is unknown or the corresponding presenter is not registered, Scene safely falls back to monochrome text.

`HighlightRequest::with_overlay` lets the host overlay additional semantic coloring ranges (the overlay wins where they overlap). `RichSpan::color` in `SelectableRichText` reuses this channel: all spans are still merged into one continuous text and a single text primitive, colored spans are written into the overlay by UTF-8 byte range, and they are resolved into final colors against the active theme's palette during Scene extraction.

## Smooth wheel interaction state

The target of line-based wheel scrolling belongs to the `AppContext`'s short-lived interaction state; `UiWorld::ScrollOffset` remains the sole authority for the current effective position. This behavior reuses the Motion IR's easing evaluation and the Runtime absolute clock, advances through `advance_animations` / `next_animation_deadline`, and requests host frames at an 8 ms sampling interval, without creating a separate timer or transform animation. Each actual move goes through the existing scroll commit path to sync hit testing, accessibility, scrollbars, and virtual lists; it does not write unscrolled layout boxes and does not trigger whole-tree layout.

Continuous input retargets from the current sampled position: same-direction input accumulates onto the target, and reverse input computes a new target from the current visible position. Public positioning APIs and pixel scrolling keep immediate semantics and cancel the transition; reduce motion makes the transition land on the target immediately. When the range changes, the target is re-clamped. When the node is unmounted or removed or the document is destroyed, the short-lived state is discarded. Idle has no scroll deadline.

Scroll samples enter the event component update only when a matching `ScrollChanged` / `UserScroll` listener exists. Without listeners, the offset commit directly provides paint, hit testing, and accessibility invalidation, and no empty event transaction is created. With listeners, the existing event transaction, observer updates, and ordering are kept: changes from the `ScrollChanged` callback are committed first, and then the effective position is read to send `UserScroll`. The hold timer for auto-hiding scrollbars is independent of subscriptions. The sampling list of active containers reuses its memory, and cancelling a callback or removing a container does not revive the transition.

## Touch scrolling and `ScrollPhysics`

Dragging, flinging, and bouncing for `PointerType::Touch` belong to the `AppContext`'s short-lived interaction state; `UiWorld::ScrollOffset` remains the sole authority for the current effective position. The host selects a profile with `AppContext::set_scroll_physics` (`ScrollPhysics::Ios`, the default; `ScrollPhysics::Android`). The profile changes only touch scrolling; wheel, scrollbar, keyboard, and `scroll_to` behave the same under both. A fling already in progress finishes with the profile it started with.

**Gesture.** A press only records a candidate, and the press reaches the control as usual. Once the finger moves more than 8 logical pixels (slop) from the press point, the gesture locks to the axis with the larger displacement (a two-axis container also moves only along this axis), and searches upward from the hit node for a `ScrollView` or an `overflow: auto|scroll` box (stopping at the root of a blocking overlay or a `position: fixed` node; `TextArea` / `RichTextEditor` do not take part). It takes the innermost container that can still scroll in that direction; if all are at their edge, it takes the innermost container with a scroll range on that axis (which lets iOS pull out the rubber band); if no container on that axis can scroll, it does not take over, and samples after the gesture are handled as an ordinary pointer. On takeover it first cancels the child control's press (`release_pointer_press`, so releasing no longer triggers a click), then captures the pointer to the container and clears that pointer's hover. Displacement is measured from the point where slop was crossed, with no 8-pixel jump. Nested scrolling is decided only once, at takeover: if the inner container can still scroll it gets the gesture, and only at its edge does the outer one; the container never changes mid-drag.

**Yielding to controls.** A control that has already captured the pointer keeps the gesture (canvases, drag handles, reorder lists, `NodePointerHooks`, and so on), with two exceptions. A horizontal `RangeField` / range slider yields only vertical drags to scrolling and ends its drag as a cancel (the value reverts to what it was before the press, and no `RangeChanged` is sent); horizontal drags still belong to the slider. Text drag-selection (input fields, selectable text) yields to scrolling; on touch platforms, selection is handled by long press and the platform. Touch does not hit scrollbar tracks and does not grab scrollbar thumbs.

**Velocity.** On release, the samples from the last 100 ms (including the release point) are fitted with a least-squares line along the locked axis, and the slope is the finger velocity. If the finger rests for more than 100 ms before release, the velocity is zero. Content velocity is opposite to the finger's.

**iOS.** When dragging past an edge, the displayed overscroll is the rubber band `(1 − 1/(x·0.55/d + 1))·d`, where `x` is the distance the finger has gone past the edge and `d` is the viewport length on that axis; a bounce that is caught resumes by inverting `x` from the currently drawn position. After release: if beyond the edge, a critically damped spring (`damped_harmonic`, stiffness 250, mass 1) returns it to the edge carrying the release velocity; otherwise velocity decays by a factor of 0.998 per millisecond, with displacement `v·(0.998^ms − 1)/ln 0.998` (`v` in px/ms). When the decay crosses an edge, it switches into the same spring at the analytically computed crossing time with the velocity at that moment, so the trajectory is identical at any sampling rate. When the remaining displacement is under 0.25 pixels, it lands on the end position.

**Android.** A port of AOSP `SplineOverScroller`: `INFLEXION = 0.35`, `DECELERATION_RATE = ln 0.78 / ln 0.9`, friction 0.015, physical coefficient `9.80665 · 39.37 · 160 · 0.84` (logical pixels are dp). The 100-segment spline table is generated with AOSP's bisection method, and `update` uses the same linear interpolation. Below 50 dp/s there is no fling; above 8000 dp/s velocity is clamped. Both drag and fling clamp at the edge, with no overscroll, stretch, or glow.

**Overscroll offset.** Only the touch path writes an offset that may exceed the range, through `UiMutation::SetScrollOverscroll`. It takes the same translate-only commit as `SetScrollOffset` (the hit index is translated by the difference, only that scroll container is re-extracted, and `update_hit_test_scroll` and virtual lists work as usual); it writes no layout boxes and triggers no layout. The next change of scroll range clamps it back into range. `ScrollChanged` / `UserScroll` and scrollbars receive the current position as usual while overscrolled (thumb geometry clamps itself).

**Scheduling.** Flinging and bouncing have no separate timer: `next_animation_deadline` folds in the earliest sample time (8 ms after the previous sample), and `advance_animations(now)` computes the position from absolute time, so the host does not need to keep producing frames, and a late wakeup lands directly where it should be at that time. Nothing leaves a deadline after it ends. When the offset is changed by any other path (`scroll_to`, pixel wheel, scrollbar drag, assistive technology, observer callbacks), the fling ends; `scroll_to` ends it even if the position does not change. When the container is unmounted, the fling is discarded; when hidden or when reduce motion is turned on, the fling ends immediately and any overscroll falls back to the edge. A finger pressed on a container that is flinging stops it, and that press does not trigger a click.
