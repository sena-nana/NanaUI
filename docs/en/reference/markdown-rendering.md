# Markdown, Image Viewer, and Rich Content Rendering

This page covers the collaboration contract between Runtime and Scene for `NativeMarkdown`, `ImageViewer`, and text input length / resizing.

## NativeMarkdown: layout, math, diagrams, and images

`NativeMarkdown` is parsed and laid out inside `nana-ui-runtime`. `UiWorld::markdown_layout` uses the current host's text shaper and the node's current content box size directly, so text selection, pointer hit activation, and Scene painting consume the same geometry. Scene expands the parsed content into ordinary text, Quad, vector path, and SVG primitives and merges them into the existing scene tree; it creates no separate Markdown window or renderer and requests no extra GPU device.

- **Inline styles and decorations**: `strong`, `emphasis`, `strike` (strikethrough), link underlines, and inline `code` surfaces all generate their paint commands directly.
- **Math (TeX)**: inline formulas take their actual rendered width during layout, and display formula blocks take their actual height, using SVG glyph outlines generated by RaTeX.
- **Mermaid diagrams**: parsed and laid out by the native diagram engine `nana-ui-diagram`, recorded against the current theme as vector paths and ordinary text, recolored automatically with light/dark themes, and sharp at any scale. A diagram takes its actual height and is scaled down proportionally when wider than the column. Each fence is laid out only once per layout pass; parse and layout results are cached by source and measurement identity, so scrolling and selection trigger no relayout. The source text is kept for box selection and copying, and `accTitle` / `accDescr` feed the accessible name and description. See [Native Diagram Engine](diagram-engine.md).
- **Failure fallback and size limits**: a formula with invalid syntax falls back to showing its source text; an unrecognized or syntactically invalid Mermaid diagram is shown as a `mermaid` code block. Math source over `16,384` bytes is rejected before the cache key is built; for Mermaid limits see [Native Diagram Engine](diagram-engine.md#failures-and-limits).
- **Async image resolution (`resolve_image`)**: async fetching and resource caching of images belong to the application. After download or decoding finishes, the application calls `resolve_image(original_source, resolved_url, width, height)` (`width` and `height` must be a nonzero intrinsic size), and every occurrence of that image in the document (including inside table cells and images with empty `alt` text) updates together. Painting uses the resolved `resolved_url`, while the `RichTextEvent::ImageActivated` event still carries the original `original_source` and `alt` text; an ordinary hyperlink sharing the same URL still fires `LinkActivated`. Submitting the same image resolution again is a safe no-op.

## ImageViewer: intrinsic size and stage zoom

`ImageViewer::intrinsic_size(width, height)` decides the initial presentation from the image's intrinsic pixel size: an image smaller than the stage's available area keeps its natural size and is centered; a large image is scaled to fit inside the stage, preserving its aspect ratio.

User zoom and pan act on the fitted size. The host texture is painted above the backdrop scrim and below the control bar, and is strictly clipped to the stage rectangle. Pointer interaction reuses Runtime layout coordinate conversion and the pointer capture lifecycle, and `Escape` goes through the unified overlay close path.

## TextInput length limit and TextArea vertical drag resizing

- **`TextInput::max_length`**: counted in **UTF-16 code units**. User typing, clipboard paste, IME composition commit, and programmatic replacement go through the same admission path: an edit that exceeds the limit is rejected as a whole, without changing the text or selection and without polluting undo history. If the initial string already exceeds `max_length`, the control does not silently truncate it; the user can still move the caret and delete characters, but the text cannot grow until its length drops below the limit.
- **`TextArea::resize_vertical(true)`**: lets the user drag the text area's bottom edge to adjust its height, and keeps the dragged height across later declarative view reprojections (while respecting explicit pixel height constraints and without emitting spurious text change events). Pointer cancel, lost capture, or the node being parked ends the drag automatically. Note: `content-box` vertical resizing is supported only when the `TextArea` has an explicit pixel height and no `min-height` / `max-height` constraint; otherwise no drag handle is shown.

## Verification commands

Changes to Markdown layout, image viewer layer order, or input box size/length constraints can be verified with these focused tests and headless probes:

```bash
CARGO_BUILD_JOBS=2 cargo test -p nana-ui-runtime --all-features --lib markdown
CARGO_BUILD_JOBS=2 cargo test -p nana-ui-diagram
CARGO_BUILD_JOBS=2 cargo test -p nana-ui-scene --features rich-text --lib markdown
CARGO_BUILD_JOBS=2 cargo test -p nana-ui --features components --test ui_contracts -- text_input_max_length text_area_resize scroll_workspace_surface
CARGO_BUILD_JOBS=2 cargo test -p nana-ui-scene --features components --test scene_contracts image_viewer_content_order
CARGO_BUILD_JOBS=2 cargo run -p nana-ui-devtools --features runtime-agent,nana-ui/components --example restored-content-probe -- target/restored-content-probe
CARGO_BUILD_JOBS=2 cargo run -p nana-ui-devtools --features runtime-agent,nana-ui/components --example diagram-probe -- target/diagram-probe
```

`restored-content-probe` renders real SVG, math, Markdown images, and host textures through the shared Scene path (covering light/dark themes and 1×/2× scale), and injects pointer drags through `RuntimeAgentSession` to verify height changes and pixels before and after. `diagram-probe` renders each Mermaid sample to PNG across the same theme and scale matrix.
